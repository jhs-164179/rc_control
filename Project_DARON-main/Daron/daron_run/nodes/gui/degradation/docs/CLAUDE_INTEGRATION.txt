현재 CDA·Depth·림 분석이 돌아가는 main 환경의 NumPy 버전을 변경하지 말 것.
Numba 설치 없이 crater_rank와 integration/record_adapter.py를 연결할 것.

1) live detector 결과의 동일 ID를 SLAM/추적 ID와 연결. 재방문 병합은
   실제 추적/위치 근거로 확인하고 appearance만으로 확정하지 말 것.
2) worker에 IR/Depth 원본, timestamp, camera K, depth scale, CDA bbox,
   다른 후보 bbox들, local terrain/pose 정보를 함께 넘길 것.
   mutable GUI 화면 버퍼를 넘기지 말고 동기화된 한 쌍을 보관할 것.
3) 관측 내벽 측정이 mesh 완성 실패와 연결되지 않도록 measure_observed
   결과를 사용. 이 어댑터의 입력 Depth는 metre, 결과 각도는 degree.
   영상별 실제 depth scale을 사용. RealOutput 실험은 0.001 m/raw-unit,
   영상 4 저장 데이터는 0.0001 m/raw-unit이었음. 서로 섞지 말 것.
4) 기존 analyze_representative_crop의 valid rim_sharpness_raw를 사용.
   S가 1보다 클 수 있음. 불러오는 단계에서 임의로 1에 자르지 말 것.
5) record_adapter.make_observation에 geometry, rim, quality를 넣을 것.
   quality에는 bbox_min_side_px, depth_valid_fraction, sync_ms,
   background_delta_deg, saturation_fraction, bbox_truncated를 제공.
   background_delta_deg는 동일 센서 샘플로 plane/quadratic 보정을 각각
   했을 때의 P95 차이. raw maximum과 P95의 차이를 넣지 말 것.
   상승 구간 수와 geometry_flags는 어댑터가 전달함.
6) make_observation의 frame_id에는 detector index를 포함해서 같은 프레임의
   서로 다른 검출을 구분. ObservationStore에 저장 후 고정 reference와
   equalweight.evaluate로 집계. mission_id를 바꿔도 다른 현장의 ID를
   임의로 같은 물체로 합치지 말 것.
7) reference.json은 검증된 초기 비교군으로 한 번 저장 후 유지.
   현장 비교 조건이 바뀌면 version이 다른 새 reference를 사용.
   실험용 reference는 실행 형식 확인용이며 현장 기준으로 승인된 것이 아님.
8) 현장 UI에서는 ranked와 preview를 구분. preview는 값 계산이 가능한
   보류 항목이며 확정 순위나 판정 성공으로 집계하지 말 것.
   audit의 결측·신호 부족은 낮은 보존도 점수 100으로 대체하지 말 것.
9) 이미지의 bbox와 계측 ROI가 동일한지 기록. 한 프레임의 이미지 아래
   대상 대표값을 표시할 경우 대표값임을 데이터 구조에 유지할 것.
10) 코드 교체 전 아래 검사를 실행:
    python -m unittest discover -s tests -v
    기존 현장 저장 IR/Depth 한 쌍으로 관측 경사·림 결과 비교.
    짧은 구간이 pending, 반복·조건이 충족된 대상이 ranked로 가는지 확인.

동일 가중치 적용은 최적 가중치의 검증 완료를 뜻하지 않음.
깊이 추정값은 이번 두 지표 식에 추가하지 않음.
실험 정확도 상승이나 CDA FPS 향상을 이 비교 모듈의 결과로 보고하지 말 것.
